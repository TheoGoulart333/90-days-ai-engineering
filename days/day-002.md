## Learn

### Topics studied

- Planning and preparing AI solutions on Azure.
- Selecting, deploying, and evaluating Microsoft Foundry models.
- Building generative AI chat applications with Microsoft Foundry.
- Extending generative AI applications with tools.
- Optimizing generative AI model performance.
- Implementing responsible generative AI solutions.

### Main concepts learned

- Generative AI applications use language models to interact with users through natural language.
- Model selection should consider the application goal, expected behavior, and evaluation process.
- Deployed models need endpoints, testing, and evaluation before being used in application workflows.
- Tools can extend a model beyond basic chat by allowing interaction with external systems.
- Prompt engineering, retrieval augmented generation, and fine-tuning are complementary optimization strategies.
- Responsible AI needs to be considered as part of the implementation, not as an afterthought.

### Main Azure services and tools covered

- Microsoft Foundry
- Foundry Tools
- Model catalog
- Model endpoints
- Responses API
- Evaluation tools

### Key insights

- Generative AI engineering is not only about calling a model; it requires planning, evaluation, integration, and governance.
- The quality of an AI application depends on how well the model behavior is selected, tested, grounded, and monitored.
- RAG, prompt engineering, and fine-tuning solve different problems and should be chosen based on the behavior required by the system.
- Responsible AI is an engineering constraint that affects architecture, testing, and release decisions.

## Reflection

### What did I learn today?

I learned how Microsoft structures generative AI application development around Microsoft Foundry: planning the solution, selecting and deploying models, evaluating behavior, building chat experiences, extending applications with tools, and applying responsible AI practices.

### What challenged me?

The main challenge was connecting the individual techniques into an engineering workflow. Prompt engineering, RAG, fine-tuning, tools, and evaluation are not isolated topics; they need to be chosen according to the problem, the data, the expected user experience, and the risk of incorrect outputs.

### How will I apply this knowledge?

I will apply this by treating future generative AI projects as complete systems: define the use case, choose the model intentionally, evaluate outputs, ground responses when needed, use tools only when they add real capability, and document responsible AI considerations from the beginning.
